## Boundaries and remaining verification

- Transfers are independent snapshots. Later converter changes do not overwrite sprite edits. Session retention is not autosave; save `.pixelforge` projects before closing. Converter presets contain settings, not media, trim, or anchor tracks.
- GIF exports have a palette, binary transparency, and 10 ms timing granularity. Projects and PNG game packs preserve full RGBA and game metadata. GIF import uses 100 ms for absent/zero delays. Existing sprite limits remain 256 frames, 512 × 512 per frame, and 16 million total frame pixels.
- API access is off by default and holds its token only for the current connection. Clients can inspect/export assets; edit access permits the documented modifications. The MCP adapter requires Node.js 24+. Remote access uses an SSH tunnel; no remote-login or firewall settings were changed. Actual remote AI-client connections were not exercised.
- Windows runtime behavior, native dialogs across all supported macOS versions, and signed update installation/restart remain unverified. Video input and alpha decoding remain system-dependent.
- Signing keys, secrets, and release/push operations were untouched. No release was published.

## Desktop workspace design overhaul — 2026-11-10

The current design treats Adjust media and Edit frames as two views of the same asset workflow. Open an image, GIF, or video; use the adjustments needed; optionally edit individual pixels and frames; then choose an output. GIF background removal can retain original dimensions and timing and export directly as GIF, MOV, WebM, or a game asset pack. Creating a game asset project is optional. Frame edits remain available when returning to adjustments, and output selection follows the user between views.

The PhotoCraft/FilmCraft reference informs the compact desktop structure: a short document header, a central canvas, a docked timeline for animation, and a focused properties inspector. Inspector tabs group related controls instead of presenting one long stack. The two views share navigation, selection states, spacing, and export placement. Advanced canvas, pivot, animation, and sheet controls remain available without occupying the primary canvas area. This is a utility layout; no promotional copy or decorative onboarding was added.

Behavioral refinements accompany the layout. Frame-duration entry accepts whole milliseconds and reports invalid input before export. Frame thumbnails use a single keyboard tab stop, with arrow navigation keeping selection and focus together. The animation-range control makes its output scope explicit: GIF and video use the selected range; game asset packs contain all frames and animation tags. GIF frame stepping follows actual frame boundaries rather than a nominal video FPS. Returning to the original source warns when newer adjustments would be discarded; it retains the separate editable-frame document.

The distinction between tools remains explicit. Background sampling chooses a color to remove, stabilization anchors move image content, the shared pivot specifies game-asset alignment, and canvas resizing changes frame bounds. Preview guides do not become exported pixels unless the user chooses the existing PNG-grid option. Export descriptions identify file contents and timing/transparency limitations.

Final visual checks corrected two canvas issues: dark/light preview backgrounds now show transparent artwork against the chosen solid color, and Fit can zoom below 1× for larger frame documents without resizing their pixels. The frame-editor header also exposes App settings directly.
